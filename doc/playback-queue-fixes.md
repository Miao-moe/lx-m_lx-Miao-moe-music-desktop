# 播放与队列修复（A01–A05）

| 编号 | 修复内容 |
| --- | --- |
| A01 | 主进程和界面的 IPC 监听统一保存实际注册的回调。取消监听可清除包装回调及重复注册，一次性监听触发后释放记录，正在分发的事件也不会再调用已取消的监听。 |
| A02 | 缓冲探测使用“当前位置 + 剩余时长的一半”作为临近结尾的目标位置，始终位于实际结尾之前。恢复播放时保留原播放位置；未知时长不盲目跳转。仅在持续缓冲约 30 秒且开启“出错自动切歌”时尝试下一首，不再因只剩少量时间就立刻跳歌。 |
| A03 | 保存实际播放队列、插队内容、调整后的顺序、当前歌曲和位置、来源及随机播放历史。暂停期间的队列调整也会保存，关闭窗口前补存最新进度。启动优先恢复队列快照，兼容旧版本的歌单与序号记录；清空队列后不会在重启时重新出现。 |
| A04 | 播放队列增加拖动手柄和“保存为歌单”。聚焦手柄后可用 Alt + ↑ / ↓ 调整顺序；移动当前歌曲不会重启音频，队列修改会使旧预加载失效。保存时可输入新歌单名称，沿用歌单中相同歌曲 ID 去重的规则并保留首次出现顺序。 |
| A05 | 增加共用的播放协调模块，统一处理切歌、队列变化、暂停、停止和定时停止的失效通知与自动切歌判断。普通切歌的异步筛选、URL 请求、缓冲恢复、预加载及无缝衔接使用相同规则；暂停保留已验证的预加载地址，同时取消尚未完成的请求。 |

## 使用说明

- 点击播放器的“播放列表”按钮，拖动歌曲左侧手柄调整队列，或聚焦手柄后按 Alt + ↑ / ↓。
- 点击“保存为歌单”，输入名称并保存。原队列仍保留，新增歌单按当前队列顺序生成。
- 重新启动后恢复上次的实际队列；是否自动播放、是否恢复进度，继续遵守原有播放器设置。
- 自动保存覆盖正常退出前的最新状态；播放进度平时合并为约两秒一次的写入，异常断电可能损失最后约两秒进度。

## 验证范围

- 监听回调的取消、一次性监听、重复注册及分发中的取消。
- 接近结尾的缓冲探测、恢复原位置，暂停、停止和退出后的定时器清理。
- 队列快照校验、旧记录兼容、插队、重复条目、清空及关闭前保存。
- 队列变动、暂停和停止期间的异步切歌与 URL 请求失效；原有无缝、交叉淡化及定时停止回归测试。
- 生产界面中的鼠标拖动、键盘排序、保存新歌单、重启恢复及再次清空。

- 播放、缓冲、预加载、无缝衔接和定时停止的逻辑测试：96 项通过。

- 相关源码 ESLint 和差异检查通过；主进程、主界面、桌面歌词的生产构建通过。
- 构建输出及测试日志位于 Git 忽略目录，没有加入源码跟踪。

实际音频设备、网络速度和系统调度仍可能影响缓冲恢复及衔接的听感；相关时序由模拟测试覆盖，界面流程使用独立测试目录中的本地 WAV 验证。
